NWC-13
======

Connection Budgets
------------------

`draft` `optional`

## Summary

This specification defines the optional `get_budget` method for querying the spending budget assigned to a Nostr Wallet Connect connection.

It builds on the request, response, discovery, and permission mechanisms in [NIP-47](https://github.com/nostr-protocol/nips/blob/master/47.md).

## Motivation

A user may want an application to see its own spending allowance without revealing the wallet's balance. A separate `get_budget` permission lets the wallet expose the connection's budget independently of `get_balance`.

Budgets are optional and can be configured by the user if their wallet supports them. This specification queries an existing budget; it does not define a method for creating or changing one.

## Discovery and permissions

A wallet service supporting this specification MUST advertise `get_budget` in its NWC info event. It MUST include `get_budget` in the `get_info` response's `methods` array when the connection is authorized to call it.

The wallet service SHOULD include `13` in the `extensions` tag of its NWC info event (kind `13194`) and in the `extensions` array of the `get_info` response's `result` object.

Permission to call `get_budget` MUST be independent of permission to call `get_balance`. The response MUST describe only the requesting connection's budget.

## Methods

### `get_budget`

Returns the budget used and the total spending limit for the connection's current budget period, together with its renewal schedule. The method takes no parameters.

Request:

```json
{
    "method": "get_budget",
    "params": {}
}
```

Response:

```json
{
    "result_type": "get_budget",
    "result": {
        "used_budget": 10000,
        "total_budget": 100000,
        "renews_at": 1693876973,
        "renewal_period": "monthly"
    }
}
```

When a budget is configured:

- `used_budget`: REQUIRED. The amount of the budget already used in the current period, in millisatoshis.
- `total_budget`: REQUIRED. The total spending limit for the current period, in millisatoshis.
- `renews_at`: OPTIONAL. The next budget reset time as a Unix timestamp in seconds. If omitted, the budget does not renew.
- `renewal_period`: REQUIRED. One of `daily`, `weekly`, `monthly`, `yearly`, or `never`.

For a renewing budget, the wallet MUST provide `renews_at`. At that timestamp, the used budget resets for the next period. For a non-renewing budget, `renewal_period` MUST be `never` and `renews_at` MUST be omitted.

The budget is a spending limit, not the wallet balance. A remaining allowance does not guarantee that the wallet has sufficient funds to make a payment.

### No configured budget

If the connection has no configured budget, the wallet MUST return an empty `result` object:

```json
{
    "result_type": "get_budget",
    "result": {}
}
```

Clients MUST distinguish an absent `total_budget` from a zero value. An empty result means no budget is configured; a zero budget is a configured spending limit of zero.

## Errors

The wallet service uses applicable NWC core errors, including `NOT_IMPLEMENTED` when the method is unsupported and `RESTRICTED` when the connection is not authorized to call it.
